# PDF 光学档案阅读器

更新：2026-09-29。此记录取代早期放在 360° 查看器内部的原型。

## 入口与架构

详情页主按钮为 **READ DOCUMENT**，收藏与 DOWNLOAD 并列。X-001 附件为明确标注的《Attention Is All You Need》技术样例，其他档案可选择本地 PDF。原 360° 查看器继续独立查看实体模型。个人论文库、元数据与期刊排列的新增行为见 `PAPER-LIBRARY.md`，以下原有视觉证据不代表已检查新增导入流程。

| 模块 | 职责 |
| --- | --- |
| archive-documents.ts | 档案与 PDF 附件关联 |
| archive-assembly.ts | 两种查看器共用六组部件、拆解深度、5.5 阻尼与完整落稳判定 |
| ArchiveScene.documentPose() | 捕获详情模型实际姿态与相机投影 |
| document-viewer.ts | 状态、相机、交互、异步取消及资源生命周期 |
| document-motion.ts | 原抬升曲线驱动的模型移动、投影阶段时长、相机直接构图路径与切片插值 |
| document-source-fade.ts | 保持原生折射捕获完整、只淡入最终模型画面 |
| pdf-document.ts | PDF.js worker、解析、受像素预算约束的栅格化 |
| pdf-layout.ts | 有限页面窗口及从左到右的空间布局 |
| pdf-slice.ts | 薄玻璃载体、真实页面、紧固件与小型竖排标识 |
| pdf-material.ts | 缩略页、投影页与高清页共同的反相材质 |

详情和文档查看器各有 WebGL 上下文；文档打开后暂停主场景。文档的拆解、显影、抽出、阅读和重组共用一个 renderer、相机与场景，复用原灯光、分辨率／纹理预算、临界阻尼、ViewerCameraMotion 和 Blender 模型。环境贴图不跨 renderer 共享。没有 iframe 或浏览器默认 PDF Viewer。

## 状态和连续过渡

    CLOSED → LOADING → CENTERING → EXPLODING → PROJECTING → ENTERING → PDF_OVERVIEW
    PDF_OVERVIEW → SELECTING → PDF_READING
    PDF_READING → RETURNING_PAGE → PDF_OVERVIEW
    换页：RETURNING_PAGE → SELECTING → PDF_READING
    退出：DISMISSING → REASSEMBLING → RETURNING_ARCHIVE → CLOSED
    载入错误：ERROR → 选择新文件 / 重试 / 退出

- 六组拆解沿用 5.5 临界阻尼。折射环组汇入光学核心并向基板投影；真实导航 mesh 先在基板上逐渐显影，再提取到左侧，不能在最终位置突然生成。
- 显影期间源盖板不写入遮挡透明页面的深度；页面完全显影后转为不透明墨层，进入 Three.js 玻璃折射预渲染。实际帧见 substrate-slides.png，避免只在状态名中“显影”、画面却被盖板挡住。
- 正常进入约 7.18 秒；先按原抬升曲线直接居中，接近落稳后衔接拆解、显影和抽出。点击切片后从当前位置抽出，高清完成后原位换纹理。换页先收回旧页再抽出新页，连续输入只执行最新目标。
- 返回档案时光学切片依次移出屏幕，源模型在中央重组，位置与速度实际收敛后直接回到原详情投影。用户已撤回光学切片归入基板的旧要求。减少动态效果直接进入终态。
- generation、AbortController、RenderTask 共同取消过期工作；失败的 loading task 也销毁 worker。关闭释放页面和模型资源，恢复入口焦点。

## 性能与发行

- 最多 7 张可见切片；thumbnail 宽 340、上限 19 万像素，最多两个并发任务。保留当前 13 页范围加投影首张与阅读页，缓存上限 15。
- 只为当前页生成高清 Canvas：正常上限 400 万像素，超级性能模式 200 万；单边不超过 4096 或硬件限制。替换后立即释放旧纹理，不常驻整份 PDF 高清页面。
- PDF.js 与匹配 worker 按需加载；字体、CMap、WASM 使用同源版本目录并进入原 PWA 离线发行包，保留 PDF.js 及各资源许可。构建 PDF.js chunk 416,511 B、worker 1,232,303 B，完整发行约 35.5 MiB。
- 文档场景使用 WebGL 原生 MSAA。高画质对照发现原全帧 SMAA／OutputPass 会忽略 PDF 的逐材质 toneMapped=false，造成纸面和文字发灰；本查看器省去该后处理，保留高清内容的颜色与反相。分辨率、DPR、材质和纹理过滤仍跟随画质预算。原模型查看器和主场景的管线不变。
- 对象计数不是 GPU 显存字节实测，也不代表所有复杂 PDF 的性能保证。扫描件、密码、表单与真实 iPhone 尚未完成专项覆盖。

## 2026-09-28 返回路径修订

用户反馈重组后模型先快速右移、再折返左侧。原因是返回时同时插值相机的世界位置、旋转和焦距，长焦详情镜头与近距离投影镜头之间的组合路径造成屏幕投影绕行。

## 2026-09-29 拆解／重组透明盖板修订

用户反馈进入和退出 PDF 时，分离的透明盖板泛白，与原 360° 查看器不同。对照代码可见两者已经共用 `ArchiveScene.createAssemblyModel()`、`CardAppearance.setClarity(1)` 和各自上下文的 `createArchiveLighting()`；差异在文档场景为衔接原详情而使用透明清屏。当前 Three.js 的 `renderTransmissionPass()` 检测到 clear alpha 小于 1，会把折射缓冲空区域替换为白色、alpha 0.5，导致没有内构遮住的盖板区域取到白色。

`DocumentViewer.transmissionBackdrop` 是一个覆盖裁剪空间的纯色绘制平面：

- 使用当前主题的线性背景色，只向原生折射预渲染的目标写入颜色，并排在内构等不透明物体之前；不写深度、不接受灯光或再次色调映射。
- 最终画布阶段关闭该平面的 colorWrite，继续透明清屏，保留详情 → 文档的原背景渐变与返回衔接。
- 盖板沿用共享清晰端点、物理透射及原显影深度规则；六组拆解／重组阻尼、返回路径、PDF 反相材质均保留。
- 不增加纹理或离屏目标；平面几何和材质随查看器释放。当前以 `getRenderTarget() !== null` 区分原生折射捕获，因为本查看器直接输出画布；若引入 composer／离屏输出或升级 Three.js，需重新检查该条件。

本次 TypeScript 编译（`tsc --noEmit`）与直接 Vite 构建通过，沿用既有主包大于 500 kB 提示。未新增或运行测试、未执行浏览器视觉复核；下方旧截图不能作为本次修订的验收证据。

## 2026-09-29 固定显影视角与返回盖板黑闪

用户截图的 HUD 为 `CLOSING`，对应拆解模型淡入阶段。旧 `setSourceOpacity()` 在淡入值小于 0.999 时把所有内构设为 `transparent=true`；Three.js `WebGLRenderLists` 将它们放入 transparent 列表，`renderTransmissionPass` 只捕获 opaque 列表。此时外盖透射 0.985 却采不到后方内构，暗色只剩背景，超过阈值后部件才重新进入捕获。同时原 0.95 处深度写入切换会突然挡住最终画布后绘制的透明内构。这是代码中与黑闪截图吻合的路径，尚未在 GPU 中截帧确认。

修订：

- 删除 `substrateCamera` 与 `dollyStart`。投影和显影始终使用原拆解观察相机，切片移入导航时直接从该构图衔接阅读相机；`frameSliceStack` 的起点同步改为 projectionCamera，避免保留旧近景投影导致跳位。
- `DocumentSourceFade` 保留源模型各材质的 transparent、opacity 与透射参数。普通不透明材质使用项目已有内构采用的 CustomBlending 标准 alpha 混合，保留 opaque 列表资格并避免 Three 的 OPAQUE shader 强制 alpha=1。已有透明标签、CustomBlending 内构与 transmissive 盖板继续各自原队列。
- 在原 shader 的 opaque_fragment 之后乘模型输出 alpha，不覆盖已有玻璃／主题 shader；原生折射预渲染的乘数为 1，最终画布为当前淡入值。深度使用原值，显影盖板只在最终画布禁写深度；不再在 0.95／0.999 阈值切换。未增加副本模型、纹理或额外离屏目标。
- 此实现与原主题背景平面一样，依赖文档查看器直接输出画布，以当前 render target 区分原生折射捕获；未来加入 composer 或额外模型渲染 pass 时必须重新检查。

针对性回归命令：`node --experimental-strip-types scripts/check-document-source-fade.mjs`。使用当前安装的 Three.js 真实渲染列表，覆盖 0、0.1、0.5、0.94、0.96、0.998、1 淡入值及显影开关，检查队列稳定、折射完整度乘数、最终 alpha、深度、原材质值与 shader 扩展保留。该检查不创建 WebGL 上下文，不代表 GPU 像素已验收。

本轮上述针对性回归、`tsc --noEmit` 和直接 Vite 构建通过；沿用既有主包大于 500 kB 提示。
