# 主页鼠标自由拖动与输入性能

2026-10-06，基线提交 `894e121`。

## 原因与修复

上轮给论文库调用 `ArchiveDrag.start(..., screenAxes=true)` 时没有区分输入设备。该模式按起始方向锁定整次手势，因此鼠标长按先横移再纵移时，后续纵向输入被忽略，斜向起步还会等待主方向判定。

鼠标现在使用原有相机投影逆矩阵，把任意屏幕路径映射到阵列平面，两条轨道都跟随指针；触摸保留明确的横向类别／纵向论文手势。模型查看器和 PDF 阅读器的角度限制没有变更。

## 拖动期间的工作量

- 移动事件继续立即采样指针与速度，并保存最新位移。真正的模型切选、标签纹理和 HUD 更新在下一次场景帧进行，同一帧只选择最终实际显示的格位。
- 移除 `navigatePlane` 对同帧最多 64 个中间格位的逐个切选；触摸横跨类别直接到最终类别并恢复记忆。自由拖动按实际物理格位选择，避免类别记忆拉偏鼠标。
- 松手前刷新最后一个待处理位置，取消、丢失捕获与失焦清空待处理位置；保留惯性速度估计、连续衰减、末尾吸附、抽取与归位。
- 静态提示、箭头文字及类别总数只在分组变化时更新；刻度标题只在条目变化时更新；收藏计数不再每切一篇扫描整库。
- 画质、阴影、AO、景深、分辨率和动效参数保持原值。

## 回归与复现

`check-mouse-pan.mjs` 在独立 Edge 临时配置中，以实际鼠标事件验证论文库和原档案库：同一次长按先水平、再垂直、再斜向反转、最后回原点，实际轨道投影误差小于 3px；折返不会变成点击。另以 24 个同帧移动事件验证只提交一次最终切选。两种库通过且无 pageerror。

`check-archive-drag.mjs` 的自由投影、惯性与触摸方向测试通过；`check-archive-wheel.mjs`、缓存／下载链路 8 项、原库 20,000 次循环检查通过。截图位于忽略目录 `verification/fixtures/mouse-pan/`。

浏览器脚本通过 `PLAYWRIGHT_MODULE` 指定已安装的 Playwright 模块，通过 `REVIEW_URL` 指向本机 Vite 服务。临时配置不使用个人浏览器数据。

## 性能测量方法

`check-drag-performance.mjs` 使用相同原档案库、1920×1080、Edge headless 和原画质，在修改前后各跑三轮。每轮 72 个显示帧，每帧分发 8 次沿原投影轨道的固定正弦路径输入，共 576 个事件；按 HUD 属性写入计数真实切选次数。选择原档案库是为了保持前后完全相同的自由投影映射，不让鼠标方向修复改变对照路径。

`inputMedianMs` / `inputP95Ms` 是每批 8 次输入事件的同步处理耗时；更新工作部分移入场景帧，因此这些指标不能单独代表总耗时或 FPS。帧间隔另行记录；结果是本机 headless 样本，不能外推到所有设备或真实 iPhone。原始数据位于 `verification/fixtures/drag-performance/`。

三轮各指标的中位数：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 每轮切选／HUD 更新次数 | 108 | 60 |
| 每批输入同步处理，中位数 | 1.3ms | 0.1ms |
| 每批输入同步处理，P95 | 2.0ms | 0.2ms |
| 显示帧间隔，中位数 | 128.4ms | 126.2ms |
| 显示帧间隔，P95 | 233.4ms | 212.9ms |

固定路径的重复切选减少约 44%。输入处理负担降低，但帧间隔中位数仅小幅改善，不能宣称整体 FPS 大幅提升或所有卡顿已经消除；本轮也没有将剩余帧耗时直接归因于某个 GPU 通道。桌面其他负载、浏览器调度和未锁定的 GPU 状态均可能影响时间样本。
